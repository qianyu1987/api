# v1.0.115 运营稳定性迭代

2026-10-13 实现；生产发布结果以 OPERATIONS_LOG.md 为准。

## 调度与流

- 每个公开模型和渠道独立保存完成响应的健康样本；24 小时窗口最近 200 个有效尝试，连续 3 次失败熔断 60 秒。API 进程缓存 10 秒。
- 兼容性先筛选；健康主渠道保持现有配置优先级，成功率下降、连续失败或 P95 响应头延迟超过渠道 timeout 时降级，再按成功率、P95、优先级和 ID 排序。原生与 Agnes 文本备用分组，保留原生优先和复杂请求保护。
- 维护 worker 每 5 分钟运行；模型目录复核至少间隔 15 分钟，仅 GET /models。目录成功且明确缺失映射目标时标记不兼容；目录查询失败不证明模型失效，不修改映射、凭据、价格。
- Terra 没有非熔断兼容原生渠道时，从 /v1/models 隐藏；直接提交在预扣前返回 503 model_maintenance 和 Retry-After: 60。
- 413 可跨渠道切换，不计入健康失败。429、503、连接失败和超时独立记录。普通参数错误不污染健康；401/403 作为渠道错误处理。
- 收到 HTTP 200 不再提前记成功；SSE 必须收到 DONE / response.completed / response.incomplete 等终止标记，且无语义错误。上限截断的 response.incomplete 是正常协议终止。
- 流失败分 client_disconnected / upstream_stream_timeout / upstream_stream_interrupted；客户端断开记录 499、排除健康失败。已输出内容不重新提交。保存首字节、完整 usage 是否到达、流时长及最终渠道；不保存内容。
- 现有失败退款语义不变，不回写历史流中断分类。健康/兼容性指标从本版本开始积累，旧 stream_interrupted 明示未分类。

## 视频闭环

- media_task_events 只记录阶段、HTTP 状态和时长。提交、接单、查询、404、网络/格式错误、完成、确认超时分别统计；404 仍查询原编号，45 分钟窗口不变。
- 接单后的额度转用量、上游编号、processing 和首次接单时间在同一事务内落地。重复 accept 不覆盖编号。429/明确队列满释放并排队；无编号模糊超时不重发。
- 模糊结果退款后保留 provider_quota_uncertain、预留秒数和并发占用；不会把未知状态视作供应商退秒。后台持续显示这类任务，即使已超过 7 天。
- 接单后失败或确认超时保留已用秒数。所有额度变更先取得 video-quota-ledger 事务 advisory lock，再取业务行锁，避免配置、预留、接单、核对与结算锁顺序冲突。锁只覆盖短数据库事务，不串行化上游生成。
- 有活动/结果未明确任务时禁止轮换 Key，避免原任务改用新凭据查询。暂停 Key 只影响新分配，原任务继续查询原渠道。
- 历史秒数优先 quota_seconds_used，回退已接单/完成任务的请求秒数，安全忽略非数字。本站账本仍不是 Agnes 实时配额。
- 后台显示接单率、查询成功率、确认超时率、404、最终完成数、保留秒数及 P50/P95。查询成功指可解析的 2xx 查询；不代表视频已完成。

## 财务与事件

- 新 /api/admin/operations 区分真实订单现金、API/媒体额度扣费、实际冻结释放、已核实渠道成本、估算成本、媒体成本快照、钱包面值负债。
- 媒体冻结释放来自 wallet_ledger，不重复从已完成收入中扣减。订阅摊销/报价不是已核实供应商账单；不据面值计算现金净利润。现有系统没有支付现金退款表，不把冻结释放称作现金退款。
- /api/me/events 仅接收登录普通用户的 visit / recharge_opened；拒绝附加字段和伪造支付/调用成功。HMAC 站内标识，不记录 IP、设备指纹、URL、提示词或 Key。
- 注册、首次成功、首次媒体和支付从已提交业务行每 5 分钟同步，支持幂等回填。回访按北京时间日历的 D1/D7/D30 统计；只纳入访问追踪开始后的注册用户和已成熟日期，不把缺失的历史访问当作未回访。事件表固定最近 30 天，经营数据可选 7/30 天。

## 保留与维护

| 数据/资源 | 策略 |
| --- | --- |
| 临时上传 | 到期 7 天后删除；活动任务引用期间保留且可读取 |
| 私有作品文件 | 完成 90 天后删除；须有 24 小时内完整备份恢复验证 |
| 已发布作品 | 不自动删除；任务、账单及价格快照保留 |
| usage_logs / relay_attempts | 沿用 USAGE_RETENTION_DAYS，默认 90 天 |
| 健康样本 / 视频诊断 | 7 天 / 90 天 |
| 每日访问、充值页事件 | 180 天；业务生命周期事件保留 |
| 数据库备份 | 每天原子 custom dump，至少保留最近 10 套及 30 天内备份 |
| 本站 Docker 镜像 | 至少保留最近 3 个、运行/停止容器引用及 rollback 标签；仅删除 relay-station 仓库 14 天前版本 |
| 构建缓存 | 仅已存在的 relay-station-cache 独立 builder 清理 7 天前缓存；共享缓存只监测，禁止全局 prune |

scripts/host-maintenance.py 默认 dry run；--verify-backup 会创建每日备份并在独立临时库完整 pg_restore，结束删除临时库和容器内副本。--apply 必须同时有本次完整恢复成功才能清理。恢复失败持久化告警并禁止清理。systemd storage timer 为北京时间每日 05:30，随机延迟最多 10 分钟。

告警：磁盘 80% / 90%；备份目录 20 GiB；本站镜像 30 个；共享构建缓存 8 / 16 GiB；单表 1 GiB；主机采样超 24 小时；支付成功超 1 分钟未到账；备份未验证/恢复失败。告警只在现有后台展示，不发送外部消息。

worker 加入 edge 网络以执行只读目录复核；PostgreSQL/Redis 仍仅 backend 网络。先执行只验证恢复的 dry run，审查清理候选后再安装每日 apply timer。
